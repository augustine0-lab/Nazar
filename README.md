# Nazar

_Команда вокруг ребёнка_ — идея платформы: все взрослые вокруг ребёнка и он сам работают по одному плану.

Веб-платформа поддержки младших школьников с трудностями внимания (СДВГ). Учитель, родитель, школьный психолог и сам ученик работают по одному плану поддержки:

- **психолог** составляет план: 1–4 цели поведения (формулировка для взрослых и для ребёнка), порог успешного дня, длину рабочего блока и перерыва, приёмы для учителя;
- **родитель** даёт согласие на обработку данных и согласует каждую версию плана; видит итог дня, неделю, выдаёт награды за звёзды, задаёт домашние задания по шагам;
- **учитель** за пару касаний отмечает цели на каждом уроке (да / нет / не оценивалось), пишет короткую заметку и закрывает день;
- **ученик** видит свои звёзды и цели своими словами, выполняет домашку по шагам с таймером и самопроверкой «Я сейчас занимаюсь заданием?», просит награду;
- **администратор школы** заводит учётные записи, классы и связи, но не видит отметок и заметок о детях.

Подробное техническое задание: https://claude.ai/code/artifact/1c55572f-4b3e-4e07-b25c-be199a1ecdb1

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
npm run setup      # создаёт базу data/nazar.db и заполняет демо-данными
npm run dev        # http://localhost:3000
```

Для показа без режима разработки: `npm run build && npm start`.

Демо-тексты (название школы, цели, награды, домашние задания, приёмы) хранятся в базе как ключи `@demo.*` и показываются на языке пользователя, поэтому одна и та же база выглядит по-русски и по-казахски. Чтобы скрыть подсказку с демо-входами на странице входа, задайте `NEXT_PUBLIC_DEMO=off` перед сборкой.

## Языки интерфейса

Русский и казахский. Язык выбирается кнопками «Рус / Қаз» (запоминается в cookie `nazar_lang`); если cookie нет, берётся язык браузера (`Accept-Language`), иначе русский. Даты и дни недели тоже форматируются по языку.

- Тексты лежат в `src/lib/i18n/messages/*.ts`: по одному словарю на раздел, у каждого ключа есть русский и казахский вариант.
- Чтобы добавить сообщение, добавьте ключ в нужный файл с обоими переводами. Тест `tests/unit/i18n.test.ts` проверяет, что у каждого ключа есть казахский перевод с теми же `{подстановками}`.
- Чтобы добавить язык, расширьте `Lang` и `LANGS` в `src/lib/i18n/index.ts` и добавьте перевод к каждому ключу.
- Казахские тексты написаны без носителя языка; перед настоящим использованием их должен прочитать и поправить казахоговорящий педагог.

## Правила, заложенные в код

Все правила вынесены в чистые функции `src/lib/domain` и покрыты тестами.

- Процент дня = «да» / («да» + «нет»); «не оценивалось» не учитывается. День успешный, если процент не ниже порога из плана (50–90 %, шаг 5).
- Учитель может менять отметки за сегодня и за предыдущий учебный день. День закрывается кнопкой или сам в 18:00.
- Звёзды: каждая отметка «да» плюс звезда за самопроверку (не больше 3 в день) минус стоимость выданных наград. Баланс считается из истории и не уходит ниже нуля.
- Новый план начинает действовать со следующего учебного дня после согласия родителя. У цели есть «линия», поэтому график продолжается через версии плана.
- Психолог получает подсказку поднять планку, если цель выполняется больше чем на 90 % две недели подряд, и упростить её, если меньше чем на 30 %.
- Без действующего согласия родителя по ребёнку ничего нельзя записать. После отзыва согласия сбор данных сразу останавливается, а через 30 дней данные удаляются командой `npm run db:purge` (её нужно запускать раз в день по расписанию).
- Вход: пароль взрослого от 8 символов, PIN ученика из 6 цифр, хранятся в виде scrypt-хешей. После 5 неверных попыток вход закрывается на 15 минут.
- Каждое изменение записывается в журнал `audit_log`.

## Тесты

```bash
npm run typecheck
npm test                                   # модульные: правила и сервисы на базе в памяти
CHROMIUM_PATH=/path/to/chrome npm run test:e2e   # сквозные сценарии в браузере
```

Сквозные тесты сами собирают демо-базу `data/e2e.db` и запускают сервер на порту 3100; перед ними нужен `npm run build`. Если Chromium для Playwright уже установлен (`npx playwright install chromium`), `CHROMIUM_PATH` можно не задавать.

Сценарии: переключение языка на казахский и обратно, выбор языка по браузеру, ошибки и уведомления на казахском, обход всех экранов всех ролей на двух языках без непереведённых строк; учитель ставит отметки и ребёнок видит звёзды; родитель выдаёт награду; психолог отправляет план и родитель его согласует; без согласия отметки недоступны; роли не попадают на чужие страницы; неверный пароль.

## Устройство

```
src/
  app/            страницы Next.js (App Router) по ролям: teacher, parent, student, psych, admin, techniques
    actions.ts    серверные действия форм, проверка ввода (zod)
  components/     общие компоненты: таймер, шаги, сетка отметок, график, звёзды
  db/
    schema.ts     схема базы (Drizzle ORM)
    seed.ts       демо-данные
    migrate.ts, purge.ts
  lib/
    domain/       чистые правила предметной области
    access/       матрица прав: кто кем приходится ребёнку и что ему можно
    services.ts   все чтения и записи с проверкой прав и журналом
    authenticate.ts, session.ts, password.ts
    i18n/         словари ru и kk, определение языка, форматирование дат
drizzle/          миграции SQL
tests/unit, tests/e2e
```

Права проверяются в одном месте (`assertCan` в `src/lib/access`) перед каждым чтением и записью, а не только в интерфейсе.

## Настройки окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_PATH` | `./data/nazar.db` | файл базы SQLite |
| `APP_TZ` | `Asia/Almaty` | часовой пояс школы: «сегодня», расписание звонков, закрытие дня |
| `NEXT_PUBLIC_DEMO` | включено | `off` скрывает демо-входы |

## Что дальше

- Для настоящей школы базу стоит перенести на PostgreSQL: в Drizzle это замена драйвера и диалекта в `src/db/index.ts`, `schema.ts` и `drizzle.config.ts`, логика сервисов не меняется.
- Данные детей нужно хранить на серверах в Казахстане: Закон РК «О персональных данных и их защите» требует этого для баз с персональными данными граждан РК. Согласие родителя версионируется (`CONSENT_TEXT_VERSION`).
- Не сделано в этой версии: уведомления родителю (почта или мессенджер), выгрузка отчёта для ПМПк, несколько школ в одном экземпляре.

## Отличие от ТЗ

В ТЗ ребёнок входил по коду от родителя. В этой версии логин и PIN ученику выдаёт администратор школы: так проще контролировать учётные записи детей и сбрасывать забытый PIN.
