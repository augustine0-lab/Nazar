# Nazar

_Команда вокруг ребёнка_ — идея платформы: все взрослые вокруг ребёнка и он сам работают по одному плану.

Веб-платформа поддержки младших школьников с трудностями внимания (СДВГ). Учитель, родитель, школьный психолог и сам ученик работают по одному плану поддержки:

- **психолог** составляет план: 1–4 цели поведения (формулировка для взрослых и для ребёнка), порог успешного дня, длину рабочего блока и перерыва, приёмы для учителя;
- **родитель** даёт согласие на обработку данных и согласует каждую версию плана; видит итог дня, неделю, выдаёт награды за звёзды, задаёт домашние задания по шагам;
- **учитель** за пару касаний отмечает цели на каждом уроке (да / нет / не оценивалось), пишет короткую заметку и закрывает день;
- **ученик** видит свои звёзды и цели своими словами, выполняет домашку по шагам с таймером и самопроверкой «Я сейчас занимаюсь заданием?», просит награду;
- **администратор школы** заводит учётные записи, классы и связи, но не видит отметок и заметок о детях.

Подробное техническое задание: https://claude.ai/code/artifact/1c55572f-4b3e-4e07-b25c-be199a1ecdb1

## Nazar как приложение (PWA)

Nazar ставится на главный экран телефона, планшета или компьютера и открывается как обычное приложение: своим значком, без адресной строки.

- **Установка.** В Chrome, Edge и на Android в шапке и на странице входа появляется кнопка «Установить». На iPhone и iPad браузер такой кнопки не даёт, поэтому на странице входа и в «Справке» написано, как добавить Nazar через «Поделиться» и «На экран Домой».
- **Манифест** (`src/app/manifest.ts`) на языке браузера: русское или казахское описание в окне установки. Значки лежат в `public/icons`, PNG рисует `node scripts/pwa-icons.mjs` из SVG.
- **Service worker** (`public/sw.js`) хранит на устройстве только одинаковые для всех файлы: код приложения, шрифты, значки и модели для камеры («Взгляд», «Сканер рюкзака»), чтобы они не скачивались заново. Страницы и ответы сервера с данными детей он **не** сохраняет: телефон или школьный планшет часто общий. Без интернета Nazar показывает экран «Нет связи» на языке ребёнка, а на открытой странице появляется плашка «Нет интернета, изменения не сохранятся». Service worker включается только на собранном сайте (`npm run build`), в `npm run dev` его нет.
- **Телефонная вёрстка.** На узком экране шапка занимает две строки: логотип с кнопками (профиль, уведомления, вид, язык, выход значком) и разделы одной строкой, которая листается вбок. Длинные плашки переносятся, а не растягивают страницу. Это проверяет `tests/e2e/pwa.spec.ts` на ширине 360 px для всех ролей.

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
npm run setup      # создаёт базу data/nazar.db и заполняет демо-данными
npm run dev        # http://localhost:3000
```

Для показа без режима разработки: `npm run build && DEMO_MODE=on npm start`.

**Режим показа.** На странице входа есть кнопка «Режим показа»: она открывает `/demo`, где можно войти за любую роль одним нажатием и вернуть демо-школу к началу. В режиме разработки он включён сам, на собранном сервере только с `DEMO_MODE=on`. На сервере с настоящими данными его включать нельзя: сброс стирает всю базу.

Демо-тексты (название школы, цели, награды, домашние задания, приёмы) хранятся в базе как ключи `@demo.*` и показываются на языке пользователя, поэтому одна и та же база выглядит по-русски и по-казахски. В демо-данных четыре недели истории отметок, так что графики и подсказки психолога сразу заполнены. `npm run db:seed` в любой момент возвращает базу к исходному состоянию. Чтобы скрыть подсказку с демо-входами на странице входа, задайте `NEXT_PUBLIC_DEMO=off` перед сборкой.

Ограничения, о которых стоит знать:

- Сводка открывается как страница для печати; PDF получается через диалог печати браузера («Сохранить как PDF»). Отдельный генератор PDF не подключён.
- Анкета написана по мотивам открытых шкал Вандербильта, но это не их официальный текст и не валидированная шкала. Ориентир «6 из 9» заимствован из них; результат нельзя считать диагнозом, и в интерфейсе это написано.
- Озвучка и диктовка работают через речевые функции браузера. Для казахского языка голоса и распознавания на многих устройствах нет; тогда приложение об этом сообщает, и ничего не ломается.
- Уведомления на экране устройства работают, пока вкладка открыта: приложение раз в минуту спрашивает сервер. Почту и мессенджеры не подключали.
- Картинки расписания и настроения это эмодзи: не нужны файлы, но вид зависит от устройства.
- Новые казахские тексты, как и прежние, написаны без носителя языка.

Ограничения, о которых стоит знать:

- Справка опирается на клинические рекомендации AAP (Wolraich и соавт., 2019), NICE NG87 и метаанализы поведенческих методов; полный список источников на самой странице. Тексты справки — краткий пересказ, перед сдачей стоит сверить их с источниками.
- Социальные истории придуманы для СДВГ по образцу метода Кэрол Грей, но сам метод изучали в основном у детей с аутизмом; в справке это сказано.
- Сравнение сна и школьного дня — простое среднее по дням, а не статистика. На экране написано, что совпадение не доказывает причину. Советов о лекарствах приложение не даёт. При выключении дневника записи удаляются сразу.
- Почта работает, только если задан `SMTP_URL`. Без него письма копятся в таблице `email_outbox`; `npm run mail:flush` отправляет накопленное. Повторной отправки неудачных писем нет.
- Выложить на хостинг из этого репозитория нельзя без вашего аккаунта у провайдера. Сборку образа и запуск контейнера проверяет CI на каждый pull request (задача `docker`).
- Демо-данные дневника сна подобраны так, чтобы сравнение что-то показывало: короткие ночи стоят перед слабыми днями. Это вымысел для показа.
- Новые казахские тексты, как и прежние, написаны без носителя языка.

## Что добавлено в четвёртой версии

Три новых направления. Они переводят платформу от помощи одному ребёнку к доказательной и инклюзивной практике всей команды и всего класса.

| Функция | Кто пользуется | Где |
|---|---|---|
| «Проверим, что работает»: психолог выбирает один приём, цель и срок (5, 10 или 15 учебных дней). Платформа сравнивает 10 учебных дней до начала с днями во время проверки, рисует график «до / во время» и даёт подсказку: помогает, в среднем лучше, но неровно, без разницы, хуже, мало данных. Психолог решает «оставить» или «отказаться» либо продлевает проверку; учитель и родители видят, что сейчас проверяется, и получают решение | психолог ведёт; учитель и родитель видят | карточка ребёнка у психолога, учителя и на главной родителя |
| Паспорт ученика для перехода: сильные стороны, интересы, что помогает, что трудно, что делать, если расстроен, связь с семьёй; плюс данные платформы: цели, приёмы, итоги проверок, успешные дни за 4 недели, команда. Можно распечатать | учитель, родитель и психолог заполняют и читают | `/passport/[id]`, кнопка «Паспорт ученика» |
| Перевод ученика в другой класс: новый учитель получает доступ и уведомление со ссылкой на паспорт, прежний теряет доступ, родители получают уведомление | администратор | «Школа» |
| «Класс для всех» (универсальный дизайн обучения, CAST UDL 3.0): 12 мер для всего класса по трём принципам со счётчиком; приёмы из планов учеников без имён и отметка, какая мера для всех их уже покрывает | учитель | «Класс для всех» в меню |
| Экран урока для проектора: что делаем сейчас, круговой таймер, что дальше, весь план; полноэкранный режим, по окончании времени ждёт учителя | учитель | `/teacher/board` |

Ограничения, о которых стоит знать:

- Сравнение «до / во время» — простой дизайн AB из исследований одного случая с мерой PEM (доля дней выше медианы базовой фазы). Это подсказка, а не доказательство: если ребёнок и так улучшался, рост «во время» мог начаться раньше. Об этом сказано на экране и в справке. Пороги (разница 10 пунктов, PEM 70%, минимум 4 отмеченных дня в фазе) выбраны для показа, их можно обсуждать.
- Одновременно у ребёнка может идти только одна проверка: если менять несколько вещей сразу, не понять, что помогло.
- Паспорт, как и остальные наблюдения, требует согласия родителя и удаляется вместе с ними после отзыва согласия.
- Соответствие приёма и меры для всего класса задаётся в справочнике приёмов (поле `class_support`). Экран урока работает только в браузере учителя и не хранит, на каком шаге урок.
- Демо: у Мираса есть завершённая проверка «Разбивка заданий на части», у Алии идёт проверка «Двигательные паузы», паспорт Мираса заполнен, в 3 «Б» отмечены пять мер для всех и готов план урока математики. Новые казахские тексты написаны без носителя языка.

## Живые тексты

Длинный параграф из учебника превращается в короткие главы, у каждой своя нарисованная картинка (идея из ролика Gemini «Bring Dense PDFs to Life», только без ИИ и без передачи данных наружу).

| Функция | Кто пользуется | Где |
|---|---|---|
| Учитель вставляет текст: главы отделяются пустой строкой, первая строка главы становится её названием. До 8 глав по 700 символов. Картинку к главе Nazar подбирает по словам (русским и казахским), учитель может поменять её в списке из 10 сцен: море, степь, горы, лес, река, небо, пустыня, зима, ночь, город | учитель класса | «Класс для всех» → «Живые тексты», `/teacher/read` |
| Чтение: слева оглавление с линией прогресса и кнопкой ▶, справа большая картинка, под ней одна глава крупным текстом. По ▶ главы листаются сами в спокойном темпе (около 75 слов в минуту), текущее предложение подсвечено, остальные приглушены. Можно поставить паузу, перейти к любой главе, листать стрелками, послушать главу вслух | ученики класса; учитель видит то же и может вывести на весь экран для доски | «Чтение» в меню ученика, `/student/read` |

Картинки нарисованы кодом (SVG): ничего не скачивается, всё работает без интернета. Движение (облака, волны, снег) останавливается в спокойном режиме и при системной настройке «уменьшить движение». Заголовки набраны шрифтом PT Serif, он есть в проекте и поддерживает казахские буквы. Тексты общие для класса, данных о ребёнке в них нет, поэтому согласие родителя для чтения не нужно. Демо: в 3 «Б» есть текст «Путешествие капли» (круговорот воды, 5 глав) на двух языках; казахский перевод написан без носителя языка.

### Плеер живых текстов

Идеи взяты из плеера [Papermorph](https://github.com/DozenTwelve/Papermorph) (MIT): голос с временем каждого слова, шаг по фразам, скорость, субтитры, сохранённое место. Код написан заново под Nazar.

| Функция | Как работает |
|---|---|
| Слово за словом | Внутри текущего предложения подсвечено слово, которое читается сейчас. С записанным голосом подсветка идёт ровно по голосу, без голоса слова распределяются по спокойному темпу (длинные слова дольше) |
| Фраза назад / вперёд | «Фраза назад» повторяет текущую фразу, а если она только началась, возвращает к предыдущей. Клавиши Shift + ← / →, пробел ставит паузу |
| Скорость | «Медленнее» (0,75), «Обычно», «Быстрее» (1,25). Голос при этом не меняет высоту |
| Субтитры | Текущая фраза поверх картинки, со словом в подсветке. На доске включены сразу |
| Голос | Демо-текст «Путешествие капли» озвучен заранее на русском и казахском (`public/voice/`), потому что казахского голоса в браузерах часто нет. Кнопка «Голос» выключает его, место в тексте сохраняется. Текст, который учитель написал сам, по-прежнему читает голос браузера |
| Место чтения | Глава и фраза запоминаются в браузере этого устройства (на сервер не уходят). При следующем открытии: «Ты остановился(-ась) на главе 2… Продолжить / С начала». Там же запоминаются скорость, субтитры и голос |

Озвучка сделана офлайн программой [Piper](https://github.com/rhasspy/piper): казахский голос ISSAI KazakhTTS (лицензия CC BY 4.0, ISSAI, Назарбаев Университет), русский голос «Irina» (данные RHVoice). Скрипт `scripts/voice/make.py` сам берёт демо-тексты из `src/lib/i18n/messages/reading.ts`, записывает MP3 и время каждого слова в `src/lib/voice/recorded.ts`; команда и ссылки на голоса в начале скрипта. Если текст главы поменяли, а голос не перезаписали, плеер это видит и читает без записи. Голоса синтетические, их стоит прослушать носителю языка.

## Взгляд Nazar

«Nazar» по-казахски значит «взгляд». Пока идёт живой текст, камера замечает, что читающий отвёл глаза, и текст ждёт его.

| Функция | Кто пользуется | Где |
|---|---|---|
| Кнопка «👁 Взгляд» под живым текстом. Перед включением камеры объясняется, что видео не записывается и не уходит с устройства, а Nazar не считает отвлечения. Затем две секунды калибровки: посмотреть на точку в середине экрана. Глаза ушли с экрана почти на секунду (или вкладка скрыта), и чтение останавливается: предложение, на котором остановились, обведено, остальной текст приглушён, чтение вслух тоже ждёт. Взгляд вернулся, и Nazar показывает «Вот где ты остановился», а через секунду с небольшим читает дальше. Моргание и короткий взгляд на ручку паузу не вызывают | ученик | любой живой текст, `/student/read/…` |
| То же для учителя у проектора: поле взгляда шире, поэтому взгляд в конспект не считается, а поворот к классу считается | учитель | живой текст учителя, `/teacher/read/…`, вместе с кнопкой «на весь экран» |

Как это устроено. Лицо распознаёт модель MediaPipe Face Landmarker (Apache 2.0) прямо в браузере. Модель (`public/vision/face_landmarker.task`, 3,7 МБ) и среда WebAssembly отдаются самим Nazar, среду копирует `scripts/vision-assets.mjs` перед `next dev` и `next build`, поэтому кадры с камеры никуда не уходят и сторонних запросов нет (это проверяет браузерный тест). Из 478 точек лица Nazar берёт поворот головы и положение радужки в глазу, сравнивает с калибровкой и решает только одно: на экране взгляд или нет (`src/lib/domain/gaze.ts`). На сервер ничего не отправляется, в базе ничего не хранится, взрослые никаких чисел не видят. Камера выключается кнопкой «Выключить» и вместе со страницей.

Ограничения, о которых стоит сказать честно. Веб-камера уверенно отличает «смотрит на экран» от «отвернулся» или «ушёл», но не видит, какую строку человек читает. Нужен свет на лице. Пороги (22° по горизонтали у ноутбука, 35° у проектора) подобраны по геометрии, а не на детях; перед показом стоит попробовать на своём ноутбуке. Полный цикл «отвернулся → пауза → вернулся → читает дальше» проверен в Chromium на тестовом видео с лицом; в CI проверяется загрузка модели, сообщение «Не вижу лица» и отсутствие внешних запросов, потому что виртуальная камера CI показывает картинку без лица. На слабом ноутбуке первая загрузка (около 17 МБ) занимает до минуты.

## Сканер рюкзака

Вечером ребёнок не просто тыкает галочки в «Рюкзаке на завтра», а показывает вещи камере, и робот отмечает их сам.

| Функция | Кто пользуется | Где |
|---|---|---|
| Кнопка «📷 Покажи роботу» в «Рюкзаке на завтра». Перед камерой Nazar пишет, какие пункты списка робот узнаёт, и что видео не записывается и не уходит с устройства. На картинке с камеры знакомые вещи обведены рамкой с подписью. Вещь, которую подержали перед камерой примерно полсекунды, отмечается сама: звучит короткий сигнал, пункт зачёркивается, появляется «Нашёл: Бутылка воды!». Одна вещь отмечает один пункт: чтобы засчитать вторую книгу, первую надо убрать из кадра. Когда робот нашёл всё, что умеет, камера выключается сама. Остальное ребёнок отмечает обычной галочкой, родителю приходит то же уведомление «рюкзак собран» | ученик | «Мой день», карточка «Рюкзак на завтра» |
| В списке «Что класть в рюкзак» у пунктов, которые узнаёт камера, стоит метка «📷 узнаёт камера», а над списком написано, что робот умеет узнавать | родитель, психолог | `/parent/schedule`, карточка ученика у психолога |

Как это устроено. Предметы распознаёт MediaPipe Object Detector с моделью EfficientDet-Lite0 (Apache 2.0, 4,6 МБ, `public/vision/efficientdet_lite0.tflite`) прямо в браузере, на процессоре, 8 кадров в секунду. Модель обучена на 80 классах COCO; из школьных вещей это книга (учебник, тетрадь, альбом), бутылка, ножницы, яблоко, банан, апельсин, бутерброд, кружка, телефон, зонт, мяч, мягкая игрушка и зубная щётка. Какой пункт списка какой вещи соответствует, Nazar определяет по словам в названии (русским и казахским) или по картинке пункта (`src/lib/domain/scan.ts`), поэтому родителю ничего настраивать не нужно. Дневник, пенал и сменку модель не знает, они остаются с обычной галочкой. На сервер уходит только сама галочка, как при нажатии.

Проверка. В Chromium на тестовом видео с фруктами робот нашёл и отметил «Апельсин на перекус» через полсекунды после появления, а при повторном показе ответил «уже в рюкзаке». Бутылку и ножницы на настоящей камере я не проверял; модель знает эти классы, но перед показом стоит попробовать при хорошем свете. Модель путает похожее (лимон может стать апельсином), поэтому вещь лучше держать целиком и на однотонном фоне. В демо у Мираса в списке есть «Бутылка воды» и «Ножницы для труда».

## Тихая комната

Дети с СДВГ легче начинают задание, когда рядом кто-то тоже работает (body doubling, как в сервисах вроде Focusmate у взрослых). Вечером ребёнок входит в комнату своего класса и видит одноклассников плиткой: «Алия · 📖 чтение · 12 мин». Взрослый может открыть комнату и вести её как продлёнку онлайн.

| Функция | Кто пользуется | Где |
|---|---|---|
| Родитель включает комнату для ребёнка, отдельно разрешает камеру и отдельно соглашается на комнату без взрослого. Выключение срабатывает сразу, и в уже открытой комнате тоже | родитель (нужно общее согласие на Nazar) | карточка «Тихая комната» на главной родителя |
| Комната класса: окна плиткой, занятие из списка (математика, чтение, письмо, язык, познание мира, рисование, другие уроки) и сколько минут ребёнок им занят, общий таймер на 10, 15, 20 или 25 минут, после таймера можно отправить друг другу 👍 (по одному на человека за круг) | ученики класса | «Тихая комната» в меню, `/room` |
| Камера, микрофон и звук других выключены, пока их не включишь. Подсказка «направь камеру на стол и руки». «Размыть фон» размывает всё, кроме середины кадра, на устройстве ребёнка: другим уходит уже размытое видео. Камеру можно выключить в любой момент, место в комнате остаётся | ученики и ведущий | `/room` |
| Ведущий: открывает комнату, запускает и останавливает таймер, выключает ребёнку камеру или микрофон (ребёнок остаётся в комнате), закрывает комнату для всех. Видит, сколько родителей включили комнату и сколько согласны на комнату без взрослого (только числа) | учитель класса, психолог детей этого класса | «Тихая комната» в меню, `/room?class=…` |

Правила, заложенные в код (`src/lib/room-services.ts`, `src/lib/room/hub.ts`):

- Только свой класс: ученик всегда попадает в комнату своего класса, адрес другого класса игнорируется. Ведут комнату только учитель класса и психолог, у которого есть дети в этом классе. Администратор школы и родители в комнату не входят.
- Без взрослого комната открывается, только если согласились родители всех учеников класса. Тогда микрофоны не работают. Если ведущий вышел из комнаты, где согласны не все, комната закрывается для детей.
- Нет чата и нет записи. Видео и звук идут напрямую между браузерами (WebRTC, каждый с каждым). Сервер Nazar передаёт только короткие служебные сообщения для соединения и список участников, на диск ничего не пишется. Занятие выбирается из списка, своего текста ввести нельзя, а 👍 не несёт ничего, кроме себя.
- Каждое действие проверяется на сервере: права читаются из базы при каждом входе, чужим соединением действовать нельзя, одно место на человека (вторая вкладка заменяет первую), не больше 12 человек в комнате.

Как устроено: живой поток событий от сервера к браузеру (server-sent events, `/api/room/events`) и запросы браузера к `/api/room`. Комнаты хранятся в памяти одного серверного процесса, поэтому при нескольких экземплярах сервера понадобится общий брокер (например, Redis). Чтобы браузеры нашли друг друга, они обращаются к STUN-серверу (по умолчанию Google, `ROOM_ICE_SERVERS` меняет его). STUN видит только сетевой адрес, не видео. В сетях, которые не пропускают прямые соединения (часть школьных и мобильных сетей), видео не дойдёт, и в окне будет «видео не дошло»; для них нужен свой TURN-сервер в `ROOM_ICE_SERVERS`. Сетка «каждый с каждым» рассчитана на маленькую комнату, для целого класса с видео нужен медиасервер (SFU).

Демо: в 3 «Б» оба родителя включили комнату с камерой, на комнату без взрослого согласна только мама Мираса, поэтому комната открывается, когда её ведёт учитель (aigul) или психолог (saule). В режиме показа у таймера есть вариант «1 мин», чтобы на показе дойти до 👍. Казахские тексты написаны без носителя языка.

## Домашка под ребёнка

Пять идей из третьего списка: ребёнок сам выбирает, как начать и как работать, а взрослые видят, сколько на самом деле стоит вечер с уроками и где ребёнку лучше сидеть.

| Что | Кто | Где |
| --- | --- | --- |
| **Кубик старта.** «Не знаю, с чего начать»: кубик выбирает задание и его первый несделанный шаг, договор только на 2 минуты, потом можно остановиться. Перебросить можно один раз, повтор того же задания исключён | ученик | главная ученика, карточка «Домашка»; `/student/homework/…?start=1` |
| **Мой звук.** Белый, розовый, коричневый шум или дождь прямо в браузере (Web Audio, без файлов и записи), громкость ограничена. Опыт на 6 учебных дней: день со звуком, день без, по очереди. Каждый ответ на вопрос таймера «Ты занят делом?» сохраняется с отметкой, играл ли звук, и Nazar сравнивает доли «да» | ученик ведёт опыт; родитель и психолог видят итог | экран задания ученика, «Домашка» родителя, карточка ребёнка у психолога |
| **Торг за задание.** Ребёнок предлагает автору задания сделку из готовых вариантов (меньше, но труднее; голосом; схемой или комиксом; в два захода; на день позже; свой вариант с парой слов). Автор принимает, отказывает или предлагает встречный вариант одним нажатием. Вторая попытка после отказа есть, третьей нет. «На день позже» переносит срок | ученик; отвечает только автор задания (учитель или родитель) | экран задания ученика; карточка ученика у учителя; «Домашка» родителя |
| **Потолок домашки.** У задания есть оценка в минутах, а у выполненного реальное время (отмечают ребёнок или родитель). Nazar складывает задания всех взрослых на 5 ближайших вечеров, считает личный темп ребёнка (во сколько раз дольше оценки, после 3 отмеченных заданий) и сравнивает с нормой для класса. Учитель, который добавил задание в перегруженный вечер, получает предупреждение, но не запрет | учитель, родитель, психолог | карточка ученика у учителя (там же можно задать домашку), «Домашка» родителя, карточка ребёнка у психолога |
| **Где мне сидится.** План класса (ряды, парты в ряду, окна слева или справа), пересадка нажатием на парту с сегодняшнего дня. Для каждого места считается доля уроков с выполненными целями карточки, текущее место сравнивается с прежним, если на каждом есть хотя бы 4 дня с отметками | учитель класса | карточка ученика у учителя → `/teacher/seat/…` |

Ограничения, о которых стоит знать:

- Нормы домашки взяты из российского СанПиН 1.2.3685-21 (1 класс 60 мин, 2–3 классы 90, 4–5 классы 120, 6–8 классы 150, 9–11 классы 210). Для школ Казахстана их нужно сверить с действующими правилами; сейчас они заданы в коде (`HOMEWORK_NORM_MIN` в `src/lib/domain/flex.ts`).
- Сравнения звука и мест показываются как подсказка, а не вывод: выборки маленькие, на результат влияют неделя, соседи и то, что ребёнок и так меняется. Исследования о белом шуме при СДВГ противоречивы.
- Пересадка хранится только для ученика с картой; остальные дети класса на плане не показаны.
- В демо у Мираса прошлые задания с оценкой и реальным временем (темп около 2,1), поэтому ближайший вечер «выше нормы»; опыт со звуком идёт пятый день; два места в 3 «Б» для сравнения; предложение сделки ждёт ответа Айгүл.
- Казахские тексты написаны без носителя языка.

Как устроено:

- Кнопка ИИ появляется, только если выполнены все условия: пользователь взрослый и у него есть право на это действие, ИИ включён в школе, родитель разрешил. Проверка в `aiGate` (`src/lib/ai-services.ts`) повторяется на сервере при каждом запросе.
- Перед отправкой имя ребёнка (все формы, в том числе с падежными окончаниями) заменяется на `[имя]`, одноклассников на `[ученик 2]`, `[ученик 3]`; в ответе имена возвращаются на место (`pseudonymize` в `src/lib/domain/ai.ts`). Фото и голос так не очистить, поэтому в подсказке у кнопки фото просят не снимать лица и фамилии.
- Gemini отвечает строго по JSON-схеме, ответ проверяется (zod). Номера целей, которых нет в карточке, отбрасываются.
- Без ключа, при исчерпанном лимите или ошибке Gemini отвечает сам Nazar по простым правилам (ключевые слова, шаблоны), и под ответом написано, кто ответил. Голосовую запись без Gemini не разобрать, её можно написать текстом.
- Модель по умолчанию `gemini-3.5-flash-lite` (бесплатный тариф, по умолчанию почти не «думает» и потому отвечает быстрее), меняется переменной `GEMINI_MODEL`, например на `gemini-3.8-flash`.

Ограничения, о которых стоит знать:

- Условия Gemini API запрещают пользователей младше 18 лет, поэтому у ученика нет ни одной ИИ-кнопки: он видит только то, что взрослый проверил и сохранил.
- На бесплатном тарифе Google может использовать присланные данные для улучшения своих продуктов, а серверы находятся вне Казахстана. Поэтому бесплатный ключ только для показа с вымышленной демо-школой. Для настоящих детей нужен платный тариф (Vertex AI или платный Gemini API) и отдельная оценка по закону РК о персональных данных.
- ИИ ошибается. Всё, что он предложил, только заполняет форму; сохраняет взрослый.
- В демо ИИ включён в школе, мама Мираса разрешила ИИ-помощь, у Алии разрешения нет (видно подсказку для учителя).
- Казахские тексты интерфейса и правил написаны без носителя языка.

## Выкладка на хостинг

Приложению нужен один процесс Node.js и диск для файла SQLite. Подойдёт любой хостинг, который запускает Docker-образ. Для настоящих данных детей нужен постоянный диск и сервер в Казахстане (см. «Что дальше»); для показа с вымышленными данными хватит бесплатного тарифа.

### Бесплатно для показа: Render

На бесплатном тарифе Render (без банковской карты) нет постоянного диска и сервис засыпает после 15 минут без посетителей. Для демо это удобно: после каждого сна база создаётся заново и демо-школа возвращается к началу. Первое открытие после сна занимает около минуты.

Быстрее всего в один клик: откройте https://dashboard.render.com/blueprint/new?repo=https://github.com/augustine0-lab/Nazar , войдите через GitHub и нажмите Apply (Deploy Blueprint). Настройки возьмутся из файла `render.yaml`. То же вручную:

1. Зарегистрируйтесь на render.com через GitHub.
2. New → Web Service → выберите репозиторий Nazar. Render сам найдёт `Dockerfile`.
3. Instance Type: Free.
4. В Environment Variables добавьте `DEMO_SEED=on` и `DEMO_MODE=on`.
5. В Advanced укажите Health Check Path: `/api/health`.
6. Create Web Service. Сборка идёт несколько минут, потом появится ссылка вида `https://nazar-xxxx.onrender.com`.
7. Для ИИ-помощи: создайте ключ в [Google AI Studio](https://aistudio.google.com/apikey) и добавьте его в Environment Variables сервиса как `GEMINI_API_KEY`, затем сохраните (Render перезапустит сервис). Без ключа ИИ-кнопки работают на простых правилах Nazar. Ключ никому не пересылайте и не кладите в репозиторий.

Перед защитой откройте ссылку за пару минут, чтобы сервис успел проснуться.

### Свой сервер или хостинг с постоянным диском

```bash
docker build -t nazar .
# демо-сервер: пустая база заполняется демо-школой, работает режим показа
docker run -p 3000:3000 -v nazar-data:/app/data -e DEMO_SEED=on -e DEMO_MODE=on nazar
# сервер для настоящей школы: без DEMO_SEED и DEMO_MODE
docker run -p 3000:3000 -v nazar-data:/app/data -e APP_URL=https://nazar.example.kz nazar
```

При запуске контейнер применяет миграции (`src/db/init.ts`) и только потом стартует сервер. Хостинг может проверять `GET /api/health`. База лежит в томе `/app/data`; резервную копию делает `npm run db:backup [папка]`, это безопасно при работающем сервере. Для удаления данных после отзыва согласия раз в день нужно запускать `npm run db:purge`.

## Языки интерфейса

Русский и казахский. Язык выбирается кнопками «Рус / Қаз» (запоминается в cookie `nazar_lang`); если cookie нет, берётся язык браузера (`Accept-Language`), иначе русский. Даты и дни недели тоже форматируются по языку.

- Тексты лежат в `src/lib/i18n/messages/*.ts`: по одному словарю на раздел, у каждого ключа есть русский и казахский вариант.
- Чтобы добавить сообщение, добавьте ключ в нужный файл с обоими переводами. Тест `tests/unit/i18n.test.ts` проверяет, что у каждого ключа есть казахский перевод с теми же `{подстановками}`.
- Чтобы добавить язык, расширьте `Lang` и `LANGS` в `src/lib/i18n/index.ts` и добавьте перевод к каждому ключу.
- Казахские тексты написаны без носителя языка; перед настоящим использованием их должен прочитать и поправить казахоговорящий педагог.

## Правила, заложенные в код

Все правила вынесены в чистые функции `src/lib/domain` и покрыты тестами.

- Процент дня = «да» / («да» + «нет»); «не оценивалось» не учитывается. День успешный, если процент не ниже порога из плана (50–90 %, шаг 5).
- Учитель может менять отметки за сегодня и за предыдущий учебный день. День закрывается кнопкой или сам в 18:00.
- Звёзды: каждая отметка «да» плюс звезда за самопроверку (не больше 3 в день) минус стоимость выданных наград. Баланс считается из истории и не уходит ниже нуля.
- Новый план начинает действовать со следующего учебного дня после согласия родителя. У цели есть «линия», поэтому график продолжается через версии плана.
- Психолог получает подсказку поднять планку, если цель выполняется больше чем на 90 % две недели подряд, и упростить её, если меньше чем на 30 %.
- Без действующего согласия родителя по ребёнку ничего нельзя записать. После отзыва согласия сбор данных сразу останавливается, а через 30 дней данные удаляются командой `npm run db:purge` (её нужно запускать раз в день по расписанию).
- Вход: пароль взрослого от 8 символов, PIN ученика из 6 цифр, хранятся в виде scrypt-хешей. После 5 неверных попыток вход закрывается на 15 минут.
- Каждое изменение записывается в журнал `audit_log`.

Остальные сценарии: переключение языка на казахский и обратно, выбор языка по браузеру, ошибки и уведомления на казахском, обход всех экранов всех ролей на двух языках без непереведённых строк; учитель ставит отметки и ребёнок видит звёзды; родитель выдаёт награду; психолог отправляет план и родитель его согласует; без согласия отметки недоступны; роли не попадают на чужие страницы; неверный пароль.
