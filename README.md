# Nazar

_Команда вокруг ребёнка_ — идея платформы: все взрослые вокруг ребёнка и он сам работают по одному плану.

Веб-платформа поддержки младших школьников с трудностями внимания (СДВГ). Учитель, родитель, школьный психолог и сам ученик работают по одному плану поддержки:

- **психолог** составляет план: 1–4 цели поведения (формулировка для взрослых и для ребёнка), порог успешного дня, длину рабочего блока и перерыва, приёмы для учителя;
- **родитель** даёт согласие на обработку данных и согласует каждую версию плана; видит итог дня, неделю, выдаёт награды за звёзды, задаёт домашние задания по шагам;
- **учитель** за пару касаний отмечает цели на каждом уроке (да / нет / не оценивалось), пишет короткую заметку и закрывает день;
- **ученик** видит свои звёзды и цели своими словами, выполняет домашку по шагам с таймером и самопроверкой «Я сейчас занимаюсь заданием?», просит награду;
- **администратор школы** заводит учётные записи, классы и связи, но не видит отметок и заметок о детях.

Подробное техническое задание: https://claude.ai/code/artifact/1c55572f-4b3e-4e07-b25c-be199a1ecdb1

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
npm run setup      # создаёт базу data/nazar.db и заполняет демо-данными
npm run dev        # http://localhost:3000
```

Для показа без режима разработки: `npm run build && DEMO_MODE=on npm start`.

**Режим показа.** На странице входа есть кнопка «Режим показа»: она открывает `/demo`, где можно войти за любую роль одним нажатием и вернуть демо-школу к началу. В режиме разработки он включён сам, на собранном сервере только с `DEMO_MODE=on`. На сервере с настоящими данными его включать нельзя: сброс стирает всю базу.

Демо-тексты (название школы, цели, награды, домашние задания, приёмы) хранятся в базе как ключи `@demo.*` и показываются на языке пользователя, поэтому одна и та же база выглядит по-русски и по-казахски. В демо-данных четыре недели истории отметок, так что графики и подсказки психолога сразу заполнены. `npm run db:seed` в любой момент возвращает базу к исходному состоянию. Чтобы скрыть подсказку с демо-входами на странице входа, задайте `NEXT_PUBLIC_DEMO=off` перед сборкой.

Ограничения, о которых стоит знать:

- Сводка открывается как страница для печати; PDF получается через диалог печати браузера («Сохранить как PDF»). Отдельный генератор PDF не подключён.
- Анкета написана по мотивам открытых шкал Вандербильта, но это не их официальный текст и не валидированная шкала. Ориентир «6 из 9» заимствован из них; результат нельзя считать диагнозом, и в интерфейсе это написано.
- Озвучка и диктовка работают через речевые функции браузера. Для казахского языка голоса и распознавания на многих устройствах нет; тогда приложение об этом сообщает, и ничего не ломается.
- Уведомления на экране устройства работают, пока вкладка открыта: приложение раз в минуту спрашивает сервер. Почту и мессенджеры не подключали.
- Картинки расписания и настроения это эмодзи: не нужны файлы, но вид зависит от устройства.
- Новые казахские тексты, как и прежние, написаны без носителя языка.

Ограничения, о которых стоит знать:

- Справка опирается на клинические рекомендации AAP (Wolraich и соавт., 2019), NICE NG87 и метаанализы поведенческих методов; полный список источников на самой странице. Тексты справки — краткий пересказ, перед сдачей стоит сверить их с источниками.
- Социальные истории придуманы для СДВГ по образцу метода Кэрол Грей, но сам метод изучали в основном у детей с аутизмом; в справке это сказано.
- Сравнение сна и школьного дня — простое среднее по дням, а не статистика. На экране написано, что совпадение не доказывает причину. Советов о лекарствах приложение не даёт. При выключении дневника записи удаляются сразу.
- Почта работает, только если задан `SMTP_URL`. Без него письма копятся в таблице `email_outbox`; `npm run mail:flush` отправляет накопленное. Повторной отправки неудачных писем нет.
- Выложить на хостинг из этого репозитория нельзя без вашего аккаунта у провайдера. Сборку образа и запуск контейнера проверяет CI на каждый pull request (задача `docker`).
- Демо-данные дневника сна подобраны так, чтобы сравнение что-то показывало: короткие ночи стоят перед слабыми днями. Это вымысел для показа.
- Новые казахские тексты, как и прежние, написаны без носителя языка.

## Что добавлено в четвёртой версии

Три новых направления. Они переводят платформу от помощи одному ребёнку к доказательной и инклюзивной практике всей команды и всего класса.

| Функция | Кто пользуется | Где |
|---|---|---|
| «Проверим, что работает»: психолог выбирает один приём, цель и срок (5, 10 или 15 учебных дней). Платформа сравнивает 10 учебных дней до начала с днями во время проверки, рисует график «до / во время» и даёт подсказку: помогает, в среднем лучше, но неровно, без разницы, хуже, мало данных. Психолог решает «оставить» или «отказаться» либо продлевает проверку; учитель и родители видят, что сейчас проверяется, и получают решение | психолог ведёт; учитель и родитель видят | карточка ребёнка у психолога, учителя и на главной родителя |
| Паспорт ученика для перехода: сильные стороны, интересы, что помогает, что трудно, что делать, если расстроен, связь с семьёй; плюс данные платформы: цели, приёмы, итоги проверок, успешные дни за 4 недели, команда. Можно распечатать | учитель, родитель и психолог заполняют и читают | `/passport/[id]`, кнопка «Паспорт ученика» |
| Перевод ученика в другой класс: новый учитель получает доступ и уведомление со ссылкой на паспорт, прежний теряет доступ, родители получают уведомление | администратор | «Школа» |
| «Класс для всех» (универсальный дизайн обучения, CAST UDL 3.0): 12 мер для всего класса по трём принципам со счётчиком; приёмы из планов учеников без имён и отметка, какая мера для всех их уже покрывает | учитель | «Класс для всех» в меню |
| Экран урока для проектора: что делаем сейчас, круговой таймер, что дальше, весь план; полноэкранный режим, по окончании времени ждёт учителя | учитель | `/teacher/board` |

Ограничения, о которых стоит знать:

- Сравнение «до / во время» — простой дизайн AB из исследований одного случая с мерой PEM (доля дней выше медианы базовой фазы). Это подсказка, а не доказательство: если ребёнок и так улучшался, рост «во время» мог начаться раньше. Об этом сказано на экране и в справке. Пороги (разница 10 пунктов, PEM 70%, минимум 4 отмеченных дня в фазе) выбраны для показа, их можно обсуждать.
- Одновременно у ребёнка может идти только одна проверка: если менять несколько вещей сразу, не понять, что помогло.
- Паспорт, как и остальные наблюдения, требует согласия родителя и удаляется вместе с ними после отзыва согласия.
- Соответствие приёма и меры для всего класса задаётся в справочнике приёмов (поле `class_support`). Экран урока работает только в браузере учителя и не хранит, на каком шаге урок.
- Демо: у Мираса есть завершённая проверка «Разбивка заданий на части», у Алии идёт проверка «Двигательные паузы», паспорт Мираса заполнен, в 3 «Б» отмечены пять мер для всех и готов план урока математики. Новые казахские тексты написаны без носителя языка.

## Выкладка на хостинг

Приложению нужен один процесс Node.js и диск для файла SQLite. Подойдёт любой хостинг, который запускает Docker-образ. Для настоящих данных детей нужен постоянный диск и сервер в Казахстане (см. «Что дальше»); для показа с вымышленными данными хватит бесплатного тарифа.

### Бесплатно для показа: Render

На бесплатном тарифе Render (без банковской карты) нет постоянного диска и сервис засыпает после 15 минут без посетителей. Для демо это удобно: после каждого сна база создаётся заново и демо-школа возвращается к началу. Первое открытие после сна занимает около минуты.

Быстрее всего в один клик: откройте https://dashboard.render.com/blueprint/new?repo=https://github.com/augustine0-lab/Nazar , войдите через GitHub и нажмите Apply (Deploy Blueprint). Настройки возьмутся из файла `render.yaml`. То же вручную:

1. Зарегистрируйтесь на render.com через GitHub.
2. New → Web Service → выберите репозиторий Nazar. Render сам найдёт `Dockerfile`.
3. Instance Type: Free.
4. В Environment Variables добавьте `DEMO_SEED=on` и `DEMO_MODE=on`.
5. В Advanced укажите Health Check Path: `/api/health`.
6. Create Web Service. Сборка идёт несколько минут, потом появится ссылка вида `https://nazar-xxxx.onrender.com`.

Перед защитой откройте ссылку за пару минут, чтобы сервис успел проснуться.

### Свой сервер или хостинг с постоянным диском

```bash
docker build -t nazar .
# демо-сервер: пустая база заполняется демо-школой, работает режим показа
docker run -p 3000:3000 -v nazar-data:/app/data -e DEMO_SEED=on -e DEMO_MODE=on nazar
# сервер для настоящей школы: без DEMO_SEED и DEMO_MODE
docker run -p 3000:3000 -v nazar-data:/app/data -e APP_URL=https://nazar.example.kz nazar
```

При запуске контейнер применяет миграции (`src/db/init.ts`) и только потом стартует сервер. Хостинг может проверять `GET /api/health`. База лежит в томе `/app/data`; резервную копию делает `npm run db:backup [папка]`, это безопасно при работающем сервере. Для удаления данных после отзыва согласия раз в день нужно запускать `npm run db:purge`.

## Языки интерфейса

Русский и казахский. Язык выбирается кнопками «Рус / Қаз» (запоминается в cookie `nazar_lang`); если cookie нет, берётся язык браузера (`Accept-Language`), иначе русский. Даты и дни недели тоже форматируются по языку.

- Тексты лежат в `src/lib/i18n/messages/*.ts`: по одному словарю на раздел, у каждого ключа есть русский и казахский вариант.
- Чтобы добавить сообщение, добавьте ключ в нужный файл с обоими переводами. Тест `tests/unit/i18n.test.ts` проверяет, что у каждого ключа есть казахский перевод с теми же `{подстановками}`.
- Чтобы добавить язык, расширьте `Lang` и `LANGS` в `src/lib/i18n/index.ts` и добавьте перевод к каждому ключу.
- Казахские тексты написаны без носителя языка; перед настоящим использованием их должен прочитать и поправить казахоговорящий педагог.

## Правила, заложенные в код

Все правила вынесены в чистые функции `src/lib/domain` и покрыты тестами.

- Процент дня = «да» / («да» + «нет»); «не оценивалось» не учитывается. День успешный, если процент не ниже порога из плана (50–90 %, шаг 5).
- Учитель может менять отметки за сегодня и за предыдущий учебный день. День закрывается кнопкой или сам в 18:00.
- Звёзды: каждая отметка «да» плюс звезда за самопроверку (не больше 3 в день) минус стоимость выданных наград. Баланс считается из истории и не уходит ниже нуля.
- Новый план начинает действовать со следующего учебного дня после согласия родителя. У цели есть «линия», поэтому график продолжается через версии плана.
- Психолог получает подсказку поднять планку, если цель выполняется больше чем на 90 % две недели подряд, и упростить её, если меньше чем на 30 %.
- Без действующего согласия родителя по ребёнку ничего нельзя записать. После отзыва согласия сбор данных сразу останавливается, а через 30 дней данные удаляются командой `npm run db:purge` (её нужно запускать раз в день по расписанию).
- Вход: пароль взрослого от 8 символов, PIN ученика из 6 цифр, хранятся в виде scrypt-хешей. После 5 неверных попыток вход закрывается на 15 минут.
- Каждое изменение записывается в журнал `audit_log`.

```
src/
  app/            страницы Next.js (App Router) по ролям: teacher, parent, student, psych, admin, techniques
    actions.ts    серверные действия форм, проверка ввода (zod)
  components/     общие компоненты: таймер, шаги, сетка отметок, график, звёзды, расписание, настроение, питомец, панель «Вид»
  db/
    schema.ts     схема базы (Drizzle ORM)
    seed.ts       демо-данные
    migrate.ts, purge.ts, init.ts (запуск в контейнере), backup.ts, mail.ts
  lib/
    domain/       чистые правила предметной области
    access/       матрица прав: кто кем приходится ребёнку и что ему можно
    services.ts   все чтения и записи с проверкой прав и журналом
    feature-services.ts  то же для расписания, настроения, питомца, сообщений, уведомлений, анкеты, итогов недели и сводки
    more-services.ts  то же для историй, рюкзака, копилки, предложений целей, дневника сна, недели, почты и выгрузки
    concept-services.ts  то же для проверки приёмов, паспорта ученика, перевода в другой класс, мер для всего класса и экрана урока
    notify.ts     кому и о чём отправляется уведомление (и письмо в очередь)
    mailer.ts     отправка писем из очереди через SMTP
    demo-mode.ts  когда разрешён режим показа
    prefs.ts      настройки вида (cookie на устройстве)
    authenticate.ts, session.ts, password.ts
    i18n/         словари ru и kk, определение языка, форматирование дат

tests/unit, tests/e2e
```

Права проверяются в одном месте (`assertCan` в `src/lib/access`) перед каждым чтением и записью, а не только в интерфейсе.

## Настройки окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_PATH` | `./data/nazar.db` | файл базы SQLite |
| `APP_TZ` | `Asia/Almaty` | часовой пояс школы: «сегодня», расписание звонков, закрытие дня |
| `NEXT_PUBLIC_DEMO` | включено | `off` скрывает демо-входы |
| `DEMO_MODE` | в разработке включён, на собранном сервере выключен | `on` включает режим показа `/demo` (вход в один клик и сброс базы), `off` выключает |
| `DEMO_SEED` | выключено | `on`: при первом запуске контейнера пустая база заполняется демо-школой |
| `SMTP_URL` | нет | адрес почтового сервера, например `smtps://user:pass@smtp.example.kz:465`; без него письма ждут в очереди |
| `MAIL_FROM` | `Nazar <no-reply@localhost>` | отправитель писем |
| `APP_URL` | нет | адрес сайта для ссылок в письмах |

## Что дальше

- Для настоящей школы базу стоит перенести на PostgreSQL: в Drizzle это замена драйвера и диалекта в `src/db/index.ts`, `schema.ts` и `drizzle.config.ts`, логика сервисов не меняется.
- Данные детей нужно хранить на серверах в Казахстане: Закон РК «О персональных данных и их защите» требует этого для баз с персональными данными граждан РК. Согласие родителя версионируется (`CONSENT_TEXT_VERSION`).
- Не сделано: уведомления в мессенджер, готовый PDF-файл без диалога печати, несколько школ в одном экземпляре, повторная отправка неудачных писем.
